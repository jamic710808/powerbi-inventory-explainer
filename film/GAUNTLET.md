# Gauntlet ledger — Power BI 庫存分析報告 圖解導覽影片

## 製作方式（與電商版、醫療版同一條管線）
- 畫面：`powerbi-desktop screenshot-all --scale 3`（Desktop Bridge）對本機 .pbip 逐頁截圖 → `make_assets.py` 裁掉視窗邊、**左上角品牌圖標打馬賽克**（使用者要求）、輸出 3840／1920／960 三種尺寸。
- 數字：影片與互動頁的數字取自畫面讀值，並用 Power BI Modeling MCP 對本機模型做 DAX 查詢驗證（首頁四數字、期間天數、準確率、各表筆數、度量值分布、關聯數）。
- 旁白：Gemini TTS（Kore）逐場景生成 → 修頭尾靜音 → `build_timeline.py` 依旁白長度排時間軸。
- 畫面渲染：`stage.html` 的 `render(t)` 是時間的純函式；`render.js` 以 puppeteer 逐格截圖 → ffmpeg。
- 配樂／音效：`mkaudio.py` 程式合成柔和鋼琴＋pad（72 BPM）與轉場音效；loudnorm 到 -16 LUFS，TP -2.0（AAC 後實測 -1.5 dBFS）。另附純配樂備援軌 `music_only.wav`。

## 第 3 輪：使用者驗收「不通過」——旁白聲音怪怪的（2026-10-09）
- **根因（我的錯，不是 Kore）**：Gemini TTS 輸出 24 kHz，`mkaudio.py` 的時間軸是 44.1 kHz，旁白沒有重新取樣就直接貼上 → 聲音被加快約 1.84 倍、音調變高，且旁白在窗口前半就念完，和字幕對不上（例：s01 旁白應 0.5–18.1 s，實際只到 ~10 s）。
- 兩位評審與我先前的音訊量測（響度、人聲 vs 配樂差）都是對這個有問題的混音做的，**無法發現**；評審明說「無法聽」，我也沒做「旁白是否落在時間窗口內」的檢查。
- **修正**：旁白先 `aresample` 到 44.1 kHz（`vo44/`），`mkaudio.py` 加取樣率斷言；重混、loudnorm；畫面不變，直接把新聲音軌封裝進影片（`-c:v copy`）。
- **新增的驗證**：逐場景比對「旁白窗口 RMS（約 0.10–0.14）vs 旁白結束後 RMS（約 0.035，只剩配樂）」，確認旁白落在 timeline 的 A～A+vo 內。
- 最終混音：−16.1 LUFS、LRA 3.4 LU、true peak −3.0 dBFS。
